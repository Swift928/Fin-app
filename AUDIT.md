**Top 5 findings by impact**

1. R-01 — `normalInverse` returns the wrong quantile outside p∈[0.08, 0.92]; Parametric and Cornish-Fisher VaR are understated by ~54% at 95% and ~45% at 99% confidence on the Risk tab, in the Thesis Lab and in the exported manifest (Critical, S)
2. R-03 — GARCH(1,1) parameters and HMM regime probabilities are hard-coded constants presented as fitted model output; persistence is 0.970 for every input series (High, L)
3. R-04 — When Gemini is unavailable the server returns canned commentary containing invented statistics with `success: true`, and the UI shows no provenance indicator (High, M)
4. M-01 — `@types/react` / `@types/react-dom` are not installed, so every React import and all JSX type-check as `any`; `npm run lint` passes vacuously and hides a real bug (High, S)
5. S-01 — The three Gemini endpoints are unauthenticated, unrate-limited and accept 10 MB bodies on a public Cloud Run URL — anyone can burn the API quota (High, M)

**Risk if no action taken:** The headline risk numbers the product exists to show are wrong at the default confidence level, and several "estimated" statistics are constants, so a quant reviewer will discredit the tool within minutes of use; that is the single largest obstacle to adoption. Because the UI never discloses that prices, fundamentals and returns are synthetic, users can act on a 68.9% "annualized CAGR" and a Sharpe of 3.09 that are artifacts of in-sample optimization on simulated data. The public AI endpoints expose the Gemini key's quota to abuse. Type checking is effectively off, so each of these fixes risks regressions no tool will catch.

## F. Growth: what would actually increase usage (outside the audit rubric)

Ranked by expected impact per hour. Do them in this order.

1. **Make the numbers trustworthy before anything else (Sprint 1 + R-03/R-04/R-05).** A quant-literate visitor opens the Risk tab, sees a 95% parametric VaR half the size of the historical VaR, and leaves. Correct math and honest labels are the price of admission; no feature outranks this.
2. **Real market data, server-side (L–XL).** Replace the seeded generator with `/api/prices?tickers=&range=` and `/api/fundamentals?tickers=` backed by one provider with a free tier (Stooq CSV, Tiingo, Alpha Vantage, Polygon or FMP), cached per ticker-day in memory (later Redis/Firestore). Keep the current generator as an explicit "Demo mode". This is the change that turns a demo into something people return to, and it dissolves R-10 (any listed ticker works).
3. **Shareable state (M).** Encode tickers, interval, rf, model and confidence in the URL (`?t=AAPL,MSFT&i=1d&rf=0.0425&m=tangency`) and restore the last session from `localStorage`. A portfolio becomes a link you can post, which is the cheapest distribution channel you have.
4. **Position import (M).** CSV upload (ticker, shares or weight) → weights, then "lock weights" so the optimizer compares *your* book against the optimal one instead of overwriting it. Brokerage sync (Plaid/SnapTrade, or the Robinhood connector you already have attached to this Claude account) can come later for your own use.
5. **README + live link + screenshots (S).** The repo currently has no README; a 60-second GIF of the Thesis Lab, the demo URL, a methodology section (what each model is and is not) and the "simulated data" disclaimer is the minimum for anyone to try it or star it. Add GitHub topics (`portfolio-optimization`, `quant-finance`, `black-litterman`, `var`, `react`, `gemini`).
6. **AI that feels live (M).** Stream Gemini responses, render Markdown (R-13), show a provenance badge (Gemini vs fallback, R-04), and make "Probe in chat" actually open the chat (R-08). Then add one high-value tool call: let the chat *run* a stress scenario or thesis evaluation and report the real numbers instead of describing them.
7. **Exports people use (M).** PNG/PDF of the current tab and CSV of weights; keep the JSON manifest but strip the regulatory claims (R-05).
8. **Mobile pass (M).** Collapse the sidebar into a drawer below `lg`, turn the nine-tab bar into a scrollable segmented control, and verify at 390 px — the first visit from a shared link is usually a phone.
9. **Measure (S).** Privacy-friendly analytics (Plausible/Umami) on tab views and AI-button clicks so the next iteration is driven by what people actually use.
10. **Keep it green (M-02).** Tests + CI are what let you ship items 1–9 weekly without re-breaking the quantile function.
